# 剩余开发批次与生命周期首批实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 先完成可独立验收的房间管理能力，再推进有审查和授权约束的自动编排。

**Architecture:** 本机偏好与复制房间状态分离；归档使用独立状态，不复用全局删除墓碑。Room 管理与 Team 执行权限分离，自动调度仍由插件强制校验。

**Tech Stack:** Node.js ESM、现有 React 面板、原子文件持久化、node:test。

**Spec:** `docs/superpowers/specs/2026-11-09-room-lifecycle-notes.md`；`2026-11-10-room-lifecycle-design.md`；M6 参考 `2026-11-10-agent-team-m6-plan.md`。

## 基线与确认

- 代码基线 `ebbe235`，版本 0.2.1，当前工作区无代码修改。
- 负责人反馈双机基本使用正常、阅读换行修复正常；不据此将全部 M4/M5 异常场景或 M1 三机清单标为通过。
- 2026-11-14 本会话确认：归档后只读，保留历史查看与已有任务核对；禁止新发言、新派发及自动唤醒，仍允许必要的已有执行结果回收、对账和取消协调。
- 静音默认不提醒，直接 @ 本机人类时仍提醒；设置可关闭 @ 例外。静音不改变 Agent 执行授权。
- 只有 Leader 可归档/恢复。其他人类成员可按历史参与资格查看已归档房间。

## Global Constraints

- 每次代码交付递增版本，同步 package.json、package-lock.json、client.js；界面/服务端显示实际加载版本。
- 不自动重载用户浏览器，不以 localhost/stub 结果冒充实机结果。
- 不使用 `retireRoom` 的不可逆 deleted 墓碑实现可恢复归档。
- 保留原数据、当前分支及历史；不合并 main、不发布 npm。
- 不把 Room 负责人变更当作 Team 或共享文档权威自动迁移。

## Review Focus

- 静音只过滤人类呈现，不能标记消息已读或阻止 Agent 唤醒。
- 本机偏好重启不丢失，并发保存不互相覆盖，写盘失败不假报成功。
- 历史资格来自可信入口，不根据客户端自报人类身份赋权。
- 旧状态合并、迟到消息和归档中的执行回执不能突破只读或丢失执行结果。
- 删除本机历史不能删除对端数据或其他房间共享的附件实体。

## 后续批次的设计冻结点
