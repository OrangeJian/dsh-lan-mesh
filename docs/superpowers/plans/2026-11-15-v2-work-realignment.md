# V2 目标与现有开发安排对齐

日期：2026-11-15。来源：负责人引用会话“研究多Agent协同”（6af91a80-0c70-83e8-b96c-f4c73723b9dd）的最新完整建设方案。本文为工作安排调整，不是第三方代码研究报告或完整G0验收报告；没有实施业务变更、运行新测试或创建提交。

## 基线与原则

本地 HEAD 17cbb37，插件0.4.0；分支codex/room-collaboration，本地跟踪引用显示领先2提交，未联网确认远端，因此不能据此排除负责人已手动推送。0.3提交8c3b4cc，0.4提交17cbb37。历史测试结果分别见版本交付回执，不视为今天重新运行。

继续采用P2P与每Team固定Leader、Worker独立工作目录/Worktree、计划先批准再执行、故障暂停并人工接管、成果审查后人工确认合并。V2.0是架构目标，不将当前包版本直接改成2.0.0。

既有开发分支提交/推送授权不等于自动成果合并授权；本次仅整理方案，不提交或推送。引用会话中的工具名和字段是目标草案，不直接当作本项目已冻结协议。

## 第一批最小任务包：G0-A与可靠性定位

允许范围建议：只读核查lib/discovery、transport、service、team-*、room-attachment-*、store与现有测试；产出docs/handoffs/g0-baseline、gap、compatibility和acceptance矩阵。缺陷整改另列明确文件及授权范围，不在大规模架构调整中顺带重写。

1. 用固定HEAD复现附件发现文件的Leader unavailable与Windows rename失败，区分UDP干扰、对端地址、生命周期与磁盘失败；保留首次失败日志，禁止靠跳过用例称全绿。
2. 确认0.4有密钥state pull强制proof的升级影响，给双机/混合版本/回退提供可执行步骤；没有迁移验证前不称完全兼容。
3. 核对DSH唤醒、运行状态、取消、重启恢复的宿主能力。发出取消请求不代表外部进程已终止；不支持的能力明确返回。
4. 把M1三机清单与真实执行证据关联；测试夹具、localhost、真实模型/物理设备三类分列。
5. 冻结第一整改任务包后再编码；不动生产分支、不合并、不部署，不清理工作区。

## 验收与开放问题

每批记录版本/SHA、环境、操作、预期/实际、日志及PASS/FAIL/BLOCKED/NOT RUN。离线目标需实际验证依赖安装、内网模型、Git、证书及外连行为，不能由“无中心服务器”直接推出完全离线可用。

后续需明确：多宿主Bridge是否确有必要；配对/ACL采用什么迁移策略；Skill版本身份；Artifact交付权限；离线依赖包形式；Leader隔离与授权迁移。第三方项目暂只列研究任务，本文不复述引用会话里的功能宣称为已核实事实。
