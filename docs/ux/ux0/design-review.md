## 3. 产品组织方式

目标是让用户沿着“发现设备 → 进入项目 → 指定成员协作 → 处理提醒 → 查看交付”完成工作，而不是把所有信息塞进一条侧栏。

四个工作领域：

| 领域 | 入口与下级页面 | 首要问题 |
|---|---|---|
| 网络 | 网络总览：拓扑 / 设备列表；设备详情；会话列表 | 哪些机器可见，哪些状态还没核对？ |
| 协作 | 收件箱快捷入口；我的项目；Room 对话 / 文档 / 任务 / 成员；发现项目；已归档 | 我在哪里讨论，哪些消息要处理？ |
| 任务 | Room 任务和 Team 执行台账分组；后续计划、Review | 谁在做什么，交付是否验收？ |
| 管理 | 本机身份；可信配置只读说明；静态连接说明；诊断；版本 | 出错怎么定位，当前加载哪个版本？ |

侧栏默认 260px（后续允许 260–288px），折叠 70px。网络、收件箱、任务是固定快捷入口；项目只出现一次。项目行 `…` 承担设置、置顶、静音、归档；发现项目只显示入口和数量，具体加入列表进入抽屉。已归档单独入口、默认不展开。

本机身份放底部，版本从标题中移出，进入身份/版本详情，同时保留界面版本与服务版本不一致时的醒目提示。不能因清理标题而丢掉版本识别能力。

## 5. 三页交互设计

### 网络总览

第一屏先显示设备、最近可见 Peer、目录会话、待核对四类摘要。数字按来源计算：`peers` 中是近期发现记录，不直接称“签名连接健康”；会话存活不计为有权派发。无来源时显示 `— / 未检查`，而不是 0 或绿色。

主视图区默认本机中心拓扑，节点是键盘可聚焦按钮；选中后打开详情。同屏最多优先展示约 10 个节点；30 节点采用完整列表、搜索与状态筛选，拓扑只作为关系入口，不能把未显示节点算作离线。每个节点以 nodeId 为身份、名称为标签；不按设备名称合并。拓扑不画 Peer 到 Peer 的连接。

图中的线仅表示本机当前可见的发现关系。发现方式、RTT、隧道、签名探测历史在当前 `peerView` 中未公开，不提供类型图例或延迟数字。静态配置与发现的区别如果需要显示，须另行审批只读视图契约；不为 UI 改传输协议。

详情展示名字、身份缩写、地址遮蔽、最近观测与会话。复制身份只复制身份字段；诊断复制先预览脱敏内容。诊断当前只有脚本，不让浏览器执行 Shell，也不虚构面板 RPC。

### Room 对话

顶部只有房间上下文和主操作；对话、文档、任务、成员四个标签并列。“任务”先显示已有 Room 任务；Team 执行单独分组，审批与 DAG 受交付门槛约束。

消息以阅读为中心，不左右大气泡铺满。作者行必须包含人类/Agent、显示名、机器；同名 Reviewer 仍能区分。Leader 标记的含义为 Room Leader，不暗示 Team/文档权威可自动迁移。

连续消息分组规则拟定为：同一 `nodeId/sessionId`、相邻不超过 3 分钟、没有系统/任务事件或引用上下文边界时合并作者头；每条消息仍保留单独 ID、时间、复制及定位。名称相同而 key 不同绝不合组。精确时间可由时间标签/详情查看。

长文字默认约 8 行后折叠，代码默认约 12 行；显示“展开全文 / 复制全文”，不截断存储内容。块级 Markdown 保留换行与代码语义，引用卡显示固定 revision/hash，远端路径只作说明。当前稿展示一条长文折叠和文档引用；连续五条与超长代码列入 UX-2 回归，不把示例图当作行为测试通过。

历史阅读时保留首个可见消息锚点与滚动偏移；只有接近底部（拟 80px）才跟随新消息；否则显示“有 N 条新消息”。前往来源支持定位 messageId，若当前接口只有 Room 跳转则先准确打开 Room，并提示无法精确定位，不假装定位成功。

Composer 与阅读列同宽，独立占布局空间，不覆盖末条消息。文档、Skill、附件标签置于文本上方；失败项就近重试。发送、上传、文档读取中分别有明确状态；失败不丢草稿。保留“设为任务”，与 M6 计划审批明确区分。预览中草稿与已移除标签在主题/布局切换时保持。

### 收件箱

保留负责人已确定的“仅未读、不显示自己发送的消息”。“全部”表示全部未读类型，不增加已读消息历史页；避免“全部/未读”两项重复。真实过滤依据不足时隐藏相应筛选，不用正文猜测任务、系统类型。

列表用两行摘要加来源和时间；整条不再加粗黑外框。选中仅查看右侧全文，不立即丢失当前处理项。独立“标为已读”成功后移出列表；“前往来源”进入 Room 后沿用现有阅读语义。全部已读先说明范围并确认，单条不用确认。写入失败保持原行与计数并给出重试，不能用前端临时减数掩盖失败。

三项目、26 条提醒都在同一列表中，默认倒序，项目/正文搜索不修改记录。后续聚合必须可展开每条消息，不能将数条提醒简单丢掉。若后端只给部分消息，过滤与计数明确标注范围，不称全量搜索。

## 6. 视觉与主题规范

| 项目 | 设计值与规则 |
|---|---|
| 层级 | 正文 14px；元信息 12px；次要时间 11–12px；模块标题 16px；页面标题 20px |
| 间距 | 4 / 8 / 12 / 16 / 24；桌面内容边距 24px，窄窗 16px |
| 圆角 | 按钮 6–7px，引用/面板 10px，Composer 12–14px |
| 表面 | 中性背景、柔和侧栏和分隔；仅选中、执行、风险状态使用浅语义底色 |
| 状态 | 正常：文字+实点；执行：转圈+文字；警告：三角/待核对；未知：问号/文字；失败：图标+原因 |
| 动效 | 仅局部状态/展开，约 120–180ms；转圈遵守减少动态效果偏好，屏外暂停 |
| 实现 | 原型色值只用于独立演示；生产使用 DSH 主题令牌，不把 :root 或 body 样式注入宿主 |

生产主题映射：基础背景取 `--dsw-alias-bg-layer-*`，正文取 `--dsw-alias-label-primary/secondary/tertiary`，边框取 `--dsw-alias-border-l1/l2`。语义色需核对安装的官方公开变量，不假造变量名；没有对应令牌时在 `.lm-workbench` 作用域定义少量语义别名并验证两种主题。

浅色主方向接近现有 DSH 的安静中性表面，蓝色只强调选择和执行，不给每个角色分配大面积不同颜色。深色保持同一信息层级和密度，不反转图像或复制另一套组件结构。

## 7. 窗口与可访问性

| 窗口 | 布局 |
|---|---|
| 1920×1080 | 260–288px 侧栏；内容居中限宽；304–344px 详情；不把聊天拉满 |
| 1440×900 | 本稿三页桌面基准；Room/网络/Inbox 可同时看主体与详情 |
| 1280×720 | 收起 Room/网络详情，保留显式打开入口；Inbox 按最小阅读宽度决定抽屉 |
| 1024×768 | 自动 70px 图标栏；设备/成员/消息详情为 360px 抽屉；不压缩 Composer 工具到不可点 |
| 390×844（探索） | 52px 导航，网络默认列表；抽屉占剩余宽度；工具只留图标并提供标签；不是本轮正式移动端支持承诺 |

键盘：Tab 遵循导航→标题操作→主内容→详情→Composer；菜单 Escape 关闭并还原焦点；抽屉关闭回到来源行；若模态则管理焦点，不让 Tab 落到被遮挡区域。预览已实现基本按钮、焦点可见与模态 Tab 约束；全面读屏与焦点恢复仍待实施验证。

目标为 WCAG AA，正文对比度至少 4.5:1、非文本重要轮廓至少 3:1；不能只凭颜色标记未读/故障。预览对比度检查只验证列出的色对，不等于全产品 AA 认证。小尺寸图标控件生产最小点击区 28–32px；重要发送操作至少 32px。

超长名字单行省略但通过详情/复制看到全名；精确 nodeId/sessionId 不变。离线或刷新失败保留旧快照并展示观测时间，不把旧绿点继续称作当前在线。归档 Room 仅阅读；空状态不诱导不可授权的操作。

## 8. 全局状态契约

预览顶部可为三个页面分别查看默认、空、加载、失败、连接中断、过期、无权限，共 21 个页面状态组合；其中默认及六种状态均截图留档。

| 状态 | 数据与交互 |
|---|---|
| Loading | 首次加载用骨架，明确正在读取；后台刷新保留内容与轻量状态，不跳回全屏骨架 |
| Empty | 网络提示检查两端服务；Room 引导邀请/开始澄清；Inbox 表示处理完毕并保留原 Room 历史 |
| Failed | 展示失败范围、保留旧数据/草稿；重试只重发对应读请求；无旧数据时专门错误态 |
| Offline | 标注本机断开/Peer 不可见的具体层级；快照过期，发送/派发不可执行，阅读仍可用 |
| Stale | 显示最后成功观测时间；未知不等于离线，不持续显示绿色健康 |
| Denied | 不显示无权正文，提供返回/核对授权；不能以“重试”暗示权限可自动获得 |
| Upload/Send failed | 区分上传失败与消息投递不确定；保留附件与稳定消息 ID，重试不制造重复消息 |
| uncertain | 任务停在待核对，不变绿，不提供“安全自动重试”；记录不代表已接受成果 |
