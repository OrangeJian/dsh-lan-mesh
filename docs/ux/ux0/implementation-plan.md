# UX-1—UX-6 分批实施计划

本计划是 UX-0 评审输出，**负责人确认设计前不执行**。以 product-baseline-v1.md 为验收契约，以 design-review.md 为拟冻结交互规则；改变协议、权限或数据结构须单独评审。

## 依赖与交付顺序

```text
UX-0 设计确认
  → 确认干净业务基线（0.4.4 或独立验收后的 0.4.5）
  → UX-1 工作区壳 / 导航
  → UX-2 Room（保留原行为）
  → UX-3 Inbox（只读未读 + 显式处理）
  → UX-4 网络（只用已观测字段）
  → UX-5a 现有任务呈现
      → M6 实际门槛和接口另行确认 → UX-5b 审批 / DAG / Review
  → UX-6 总体验收
```

UX-5b 不阻塞 UX-1—4；M6 真实多机门槛没有通过时，只交付已有执行台账的只读呈现，不能把禁用原型算作 M6 交付。每批负责人检查后再冻结下一批视觉细节。GitHub 推送持续暂停。

## 工程组织与可改范围

拟新增 `ui/` 源目录，分 `shell/`、`room/`、`inbox/`、`network/`、`tasks/`、`models/`、`shared/`；产物继续为宿主现有 `client.js` 入口。构建依赖尽量复用现有环境，若引入新构建工具则先提交依赖/产物方案评审，包含离线安装与 package.files 影响。不可简单把未打包的本地相对 import 放进 ModuleLoader。

第一步先做纯 ViewModel 与样式作用域，再逐页迁移渲染；不同时改业务状态或消息发送副作用。根 `MeshPanel` 负责现有数据订阅与命令，子组件接受模型与事件；局部 UI 状态如抽屉/选中/筛选留在组件内，草稿由明确的 Room key 管理。

不可在 UI 批次中修改的核心：`lib/transport.mjs`、Room/Team 状态机、附件存储/签名、执行授权、文档权威和数据结构。只读数据不足时先写契约差距，缩减未证实的状态展示，或提交独立接口扩展提案，不能偷偷补端点。

## UX-1 工作区壳与导航

建议 3 个可独立审阅的小批次，约 2–3 个工作日（含回归和修正的粗估，不作时间承诺）。

### UX-1a 模型与主题壳

- [ ] `models/workbench-model`：把 snapshot/agents 转成现有字段的视图；分别保留 loading / unavailable / empty，测试缺失字段、名称冲突、旧节点。
- [ ] `shared/status-indicator`、`theme`、`surface-state`：状态图标/文字、作用域变量、空/失败/过期/无权限；深浅一致，减少动态效果。
- [ ] `shell/workbench-layout`、`workspace-header`、`details-drawer`：侧栏、标题、主体、详情统一布局；先挂旧页面，避免入口消失。
- [ ] 核对宿主公共 ModuleLoader、React、主题与构建产物；保留 0.4.4 对外接口。界面/服务版本分别展示，不一致有明显提示。

### UX-1b 导航与项目

- [ ] `shell/navigation-rail`：固定网络/收件箱/任务入口；70px 折叠；键盘可达。
- [ ] `project-tree`：单行项目身份、未读、置顶、行尾菜单，超长名称；不按同名合并。
- [ ] `discover-projects-drawer`：复用 rooms.all/mine 做可加入投影；同名 Room 用 Room ID 与 Leader 设备消歧；加入过程 loading/error 保留原反馈。
- [ ] `project-menu` / `archived-projects`：调用原 roomPreferences/roomLifecycle；归档只读、静音 @例外、置顶等语义不变。没有接管/删除能力不显示可执行项。
- [ ] `identity-popover`：本机名、nodeId、界面版本/服务版本/不一致提示、管理入口。

### UX-1c 状态和回归

- [ ] 无 Room、断开、加载失败、超长中英名称、3 个同名项目与侧栏折叠检查。
- [ ] 导航切换不清草稿，旧路由/用户入口均可达；返回 Room 保持选择。
- [ ] 对应 A01/A02/A09/A13/A14/A15；panel、schema、composer 及相关 Room/偏好测试。
- [ ] 同一分辨率、同类数据的改前/改后截图；不使用当前原型的示例数字冒充生产数据。

退出条件：P-01/P-02 有真实可运行界面证据；功能入口不减少，数据未迁移。风险：宿主 Rail 注册与主工作区布局可能相互影响；先保留旧页面挂载，验证再移除旧导航。

## UX-2 Room 聊天

建议 4 个小批次，约 3–5 个工作日。依赖 UX-1，受 0.4.5 引用能力是否稳定提交影响。

### UX-2a 消息模型和作者

- [ ] `models/message-model`：以消息 ID 和 nodeId/sessionId 为身份；只做显示投影，不改 mentions、签名、text 或 skillRefs。
- [ ] `room-header`、`room-tabs`、`member-summary`：对话/文档/任务/成员；原文档组件继续挂载，任务不混入暂停的 M6 计划草稿。
- [ ] `message-group`、`author-line`、`message-actions`：3 分钟同作者分组边界、精确时间、复制/定位；跨机器同名不得合组。

### UX-2b 阅读体验

- [ ] `message-body`：保留换行、Markdown、代码；长文/长代码折叠与全文复制，不改原始数据。
- [ ] `system-event` / `task-event`：使用已有明确类型，无法判定的旧消息保持普通消息，不从字面猜事件。
- [ ] `reference-card` / `attachment-card`：文档固定修订、图片、文件、下载/传输失败；远端路径仅作来源说明。
- [ ] `message-timeline`：阅读列限宽 900px；滚动锚点、新消息计数、跳到底部；默认不把历史阅读拉走。

### UX-2c Composer 和 Room 上下文

- [ ] `room-composer-frame` 只负责布局，保留原输入、附件/图片、Skill、精确成员 mentions、@文档与设为任务逻辑。
- [ ] `context-reference-tray`：按稳定 ID 移除文档、Skill、文件；异步读取中不发送不完整上下文；来源设备、版本不挤入正文。
- [ ] `composer-feedback`：分别处理上传、读取、发送、不确定投递、权限拒绝；稳定 ID 重试、失败保留草稿；跨房间迟到结果不覆盖新草稿。
- [ ] `room-context-panel`：文档、成员、当前任务摘要；没有能力数据时清楚标注未知，不能把 Peer 在线当 Agent 运行。
- [ ] 若 0.4.5 未稳定提交，任务成果引用暂不暴露可操作选择；保留对应插槽和“尚未交付”说明，不拿 UI 改造替代成果授权校验。

### UX-2d 验证

- [ ] 连续 5 条同作者、同名异机、长代码、中文换行、超长身份、系统事件边界。
- [ ] 文本、@Agent、@文档固定 revision/hash、Skill 提示、图片粘贴/拖拽、多附件失败重试、设为任务。
- [ ] 当前 Room 已读与收件箱计数协调、切换 Room 保留草稿、归档只读、发送权限失败。
- [ ] A02/A05—A09/A13—A15；复用已有 panel/context/attachment/Room 回归，并做两节点真实操作。

退出条件：P-05/P-06/P-10 改善有生产截图和操作证据，所有原发送通道不变。风险：分组造成消息 ID/滚动丢失，组件拆分导致异步请求过期守卫失效，Markdown 处理引入注入面；逐项负例验证。

## UX-3 收件箱

建议 3 个小批次，约 2–3 个工作日。

### UX-3a 只读模型与列表

- [ ] `models/inbox-model`：严格沿用未读与排除自己消息规则；分类只接受已有结构化字段。
- [ ] `inbox-toolbar`：全部未读类型/@我/任务/系统，仅对可判定数据启用；正文/项目搜索与范围提示。
- [ ] `inbox-list` / `inbox-row`：两行摘要、来源 Room/作者/机器、时间和未读指示；无全文展开大卡片；26 条/3 项目样本。

### UX-3b 详情与处理

- [ ] `inbox-detail`：全文、关联来源、明确“标为已读”；窄窗抽屉，Esc 返回列表并还原焦点。
- [ ] `read-action-controller`：调用原 markRead 成功后刷新权威 snapshot；保存失败保留当前行与计数，允许重试；并发新消息不因旧响应被清空。
- [ ] `mark-all-confirm`：说明当前节点范围，不删除来源记录；确认期间保留新提醒的处理边界，使用原接口定义，不擅自发明批量选择协议。
- [ ] 前往 Room 后继续调用现有 roomRead；精确 messageId 定位若无契约支持则明确只跳房间。

### UX-3c 验证

- [ ] 26 条、3 项目、超长正文、多次同任务提醒；筛选不丢条目；选中不自动丢失当前项。
- [ ] 单条/全部已读成功与失败、响应乱序、断开重连、当前窗口 Agent 回复、新消息与清空并发。
- [ ] A03/A04/A09/A13—A15；panel 与已读存储相关回归；两节点真实计数和来源跳转。

退出条件：P-03/P-04 改善可量化（1440×900 主列表约显示 6–8 条而非巨卡；两行摘要）；未读数字与持久记录一致。风险：分类字段不足、全部已读与新消息竞争、前端选中和已读混用。字段不足的分类隐藏，不猜测。

## UX-4 网络总览

建议 3 个小批次，约 3–4 个工作日；只依赖现有只读数据。若需新字段，契约审批时间另计。

- [ ] Node/Agent ViewModel，明确发现记录、会话、运行、授权四层；地址展示默认遮蔽。
- [ ] 平等的拓扑/列表；本机中心布局、搜索、选择详情；不显示 Peer 间未观测边。
- [ ] 1/3/10/30 节点，多重名、长名、消失/恢复、未知数据；30 节点默认列表，关系图只做辅助。
- [ ] 刷新与后台退避、组件卸载取消、窗口不可见减少工作；不无节制重复 agents 请求。
- [ ] 诊断说明复用已有脚本；若需要浏览器读取报告先提只读接口契约，不使 UI 执行命令。
- [ ] A10/A13/A14/A15；真实两节点发现/失联/恢复与隐私检查。没有物理多机结果就标 NOT RUN。

退出条件：网络状态措辞与真实字段一一对应，无编造 RTT、隧道、健康绿灯。风险：节点 lastSeen 只证明发现、静态来源未公开、远端 agent status 缺失。始终保留 unknown 与观测时间。

## UX-5 任务工作区

UX-5a 约 2–3 个工作日；UX-5b 随 M6 真实交付评估，暂不承诺完成日。

- [ ] 先区分 Room 任务与 Team Task，来源、负责人、设备、attempt、执行与验收状态分别展示。
- [ ] 现有 Team 工具能力若要挂面板，先审批只读 `teamStatus` 视图端点及 owner/caller 权限；禁止复用未提交 teamPlan 草稿偷渡。
- [ ] Execution succeeded 显示“已提交 / 待审查”，Task accepted 才为“已验收”；uncertain 需要人工核对，不能以重试按钮触发新 attempt。
- [ ] M6-A 批准绑定版本、范围、参与者和权威的实际接口后，才接入计划草稿/差异/批准 UI。
- [ ] M6-B 真正满足真实 M1 门槛与依赖/容量门禁后，才开放 DAG 操作。
- [ ] M6-C 证据、测试、Review 与人工合并接口实际可用后，才出现对应操作。远端文件声明不等于附件或已合并提交。
- [ ] A11/A12/A14；权限、过期批准、leader 离线、拒绝 Review、不确定状态均要验证。

## UX-6 总体验收

建议 1–2 个工作日，依赖交付范围明确，不把未实现 M6 包装成 UI 完成。

- [ ] 1920×1080 / 1440×900 / 1280×720 / 1024×768，深浅主题、展开/折叠导航、详情抽屉截图。
- [ ] 键盘与读屏抽查、焦点还原、对比度、减少动态效果、长名字与中文/英文混排。
- [ ] 15 项 UX-A 场景逐项记录 PASS/FAIL/NOT RUN，挂截图/日志/版本/SHA。
- [ ] panel-check、schema-check、composer-compat、相关行为测试；完整 suite 在实际稳定基线跑，不沿用历史数量。
- [ ] 至少一次真实浏览器目测与两节点验证，三机/M1门槛仍独立记录；不以 mock 或 localhost 代替物理结果。
- [ ] 每批版本号递增、界面与服务版本可核对、本地提交；推送继续等待单独指令。

粗估 UX-1—4 与总体验收合计约 11–17 个工作日，取决于宿主组件拆分、数据接口和验收反馈；这是排期粒度说明，不是已完成量或对日历日期的承诺。可压缩范围按批交付，但不以隐藏未完成能力称整体完成。

## 每批交付与停止线

每批列明：实际分支/SHA、界面/服务版本、保护清单校验、改动组件、真实数据字段、截图、检查命令与数量、未完成/风险。进入下一批前先处理阻塞缺陷。

出现新端点、协议/安全/数据迁移、自动选主/接管/合并、工作树成果覆盖风险时停止该项并提具体契约；不停止无依赖的已授权设计/验证工作。UX-0 结束后必须等待负责人确认，不能自动推进 UX-1。
