# v0.4.8 样式热重载修复

用户的实际0.4.7截图显示新代码与服务已加载，但品牌仍同行、项目操作仍落在下一行。复现发现：installStyles遇到同ID节点直接返回，因此热重载保留了旧CSS。旧panel harness的getElementById返回undefined，也导致样式注入被跳过而未被检查。

修复：复用同一插件style标签，内容变化时原位更新CSS，并标记data-lan-mesh-version；相同内容重复安装不增加标签。仅修改自己的样式节点，宿主样式保持不变。panel harness按真实DOM返回null并保留style对象，新增启动样式检查。

证据：旧样式重载测试先失败后通过；最终完整410/410、panel222/222、Schema82/82、Composer兼容PASS、构建一致性通过。浏览器同一fixture前后验证：品牌改为纵向分层、项目行flex、唯一style且标记0.4.8、重复安装无副本、宿主探针颜色不变，菜单在示例视口内。见ux1c-style-preview/preview-validation.json与3张取证截图。

上述浏览器取证使用实际安装函数和头部、示例DOM，不等于已在用户DSH重载验证。真实操作仍由负责人核对。本次不改变协议、数据、Room发送或执行权限；原0.4.5/M6草稿不包含在该分支。

版本0.4.8，加载目录不变。插件重新加载时将自动替换已有样式，无需以清空缓存或丢弃房间数据作为修复方式。继续推进UX-1其余事项，未将整个UX-1或UX升级宣布完成。仅本地提交，不推送。
