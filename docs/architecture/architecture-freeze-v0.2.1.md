# 架构冻结决议 V0.2.1

状态：负责人已批准。批准日期：2026-11-17（Asia/Shanghai）。批准依据：负责人在本会话对V0.2.1五项候选决策明确回复“批准”。本决议与agent-workspace-execution-merge-v0.2.1.md共同组成冻结基线；候选文档中的待批准状态以本决议为准，历史评审记录不覆盖。

| 决策 | 冻结内容 |
|---|---|
| C-01 Agent身份 | 唯一管理节点；首期不跨设备迁移、不跨设备运行同一Agent身份；远程协作采用独立Agent委托 |
| C-02 Team/Room | 保留现有一个Room至多一个执行Team；暂不开放多Team共享 |
| C-03 Human Owner | 默认仅可只读本人当前有权管理的Room/Team必要字段；敏感执行日志和私有路径需额外授权，不自动取得全网管理员权限 |
| C-04 仓库与隔离 | 节点预配可信仓库，核对repoId/baseCommit；代码任务独立Worktree，不自动同步任意目录 |
| C-05 Runner顺序 | Native Session适配先行；独立目录、写权限与隔离未验证前禁止代码写入；Headless通过能力/恢复验证后独立启用 |

## 同时生效的约束

- 保留原五项ADR：P2P与固定Leader、独立目录/Worktree、计划人工批准、Leader故障暂停并人工接管、Review后人工合并。
- 批准绑定Team、Plan revision/hash、任务集合、Workspace及执行权限范围；执行前重新核对当前ACL，撤权优先。
- 无法确认当前generation、批准有效性或Workspace权限时拒绝新的副作用，已发生执行保留证据并核对。
- Runner恢复记录不是第二套Task/Execution账本；uncertain不自动重试有副作用执行。
- Owner身份必须由可验证宿主身份或负责人批准的等效机制建立。该接口及权限映射仍待契约核实，批准权限原则不代表接口已实现。

## 授权与下一步边界

本次是架构决策冻结，不是M6开发恢复、真实任务执行、Headless上线、工作树迁移或GitHub推送授权。下一步依据V0.2.1第七节形成分批实施计划和接口契约，逐项核实既有一致性修复、G2、UX与M1真实多机证据；缺失项仍为待验证。
