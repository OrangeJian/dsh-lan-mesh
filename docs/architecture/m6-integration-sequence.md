# M6 接入顺序

基线 `7739c9d`。先用本地隔离测试完成开发，真机验收集中进行。

| 批次 | 文件归属与依赖 | 验收 |
|---|---|---|
| 批准与评审逻辑 | 独立预览与结果评审模块，并行开发 | 内容或版本变化使旧批准失效。评审绑定确切的执行与成果哈希。 |
| 账本接入 | 待 R2 的 `team-store.mjs` 变更和 M6 纯函数合入，再修改 Team reducer 与 store | 旧账本可打开，计划、批准与评审记录使用现有事务。拒绝冲突版本、旧代次及重放篡改。 |
| 人类入口 | 账本命令与 Host 身份确认后，接只读预览及批准、评审动作 | 从服务端解析当前身份。普通成员和已撤权用户无法批准。固定引用仍需通过成果访问授权。 |
| 调度接入 | 现有 Coordinator 与 Worker 的准入路径，默认关闭 | 计划已批准、依赖已验收、授权与容量仍有效才入队。拒绝后重做使用新执行 ID，未知执行继续占槽。测试用替身验证入队、唤醒和恢复。 |

计划、批准及验收持久化使用同一 Team 账本。模块预览的候选列表不能作为准入凭证。Coordinator 在入队前重新读取账本并核验批准内容、revision、Team 代次、ACL 和占槽，Worker 继续执行现有本机准入检查。DAG 的 Team 范围由调用方从权威账本显式传入。

保持现有 M1 单槽、固定 Leader 和人工对账规则。额外双签、代次迁移和本机执行语义另行确认。接入开发可用合成上下文和隔离账本验证，真实派单待实机验收。
