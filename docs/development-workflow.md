# 开发协作规范

负责人决定方向与重大取舍；Codex 负责现状核对、设计、任务拆解、审查和验收；DSH 或负责人指定的实施 Agent 负责业务实现与测试。本轮仅文档整理。

流程：Codex 方案 → 负责人确认 → 冻结交接批次 → DSH 实施 → 提交实际变更/测试/偏差 → Codex 独立复验 → 负责人确认 → 更新 ROADMAP。

- 未确认前不得开始交接批次、自动调用开发 Agent、合并、发布或修改协议。
- 实施者可自主决定非破坏性局部细节；涉及数据模型、协议、权限和核心架构时，记录建议与影响并等待确认。
- 保留现有分支、Worktree、未提交修改，不 reset、清理或擅自合并。
- 交付包含 base/head SHA、文件清单、测试命令及退出码、异常场景、未解决问题、设计差异与部署要求。
- 测试通过与实机验收分开记录；禁止把 stub runtime smoke 称为真实跨设备 Agent 验收。
- Codex 审查代码和独立回归，不仅采信报告；整改仍交实施者，复验后才关闭。
- `.superpowers/sdd` 是忽略的本地台账，正式交接不得只依赖该目录；关键状态必须同步到受版本管理的 ROADMAP 和交接文档。
