# 0.4.0 房间归档与恢复

日期 2026-11-14；基线为0.3.0提交 `8c3b4cc`。本批实现归档/恢复与历史入口，未实现退出/本机删除、负责人移交/无主接管、M6 或输入框 @ 文档。

## 使用

所有机器同步开发分支、在仓库运行 npm ci 后重新加载，核对界面/服务端均为0.4.0。人类 Leader 在左栏房间设置点“归档房间”；房间从平时列表隐藏，通过“已归档”展开阅读，由原人类 Leader 恢复。历史人类资格独立保存，退出后不因当前成员缺失而抹掉已经记录的资格；旧盘只能补现存人类成员，过去已离开的资格无法凭空恢复。

归档保留每端自己的数据与事件记录，不写 deleted。归档状态按独立generation合并，不被旧active状态回灌撤销。聊天/文档/附件历史仅历史人类可读，新发言、上传、新文档写入、加入/邀请/改名、新任务和新唤醒被拒绝。原有任务结果、核对和取消协调保留。

Team归档期间临时禁止新派发/开始，运行中执行仍可心跳和回报，不改永久权限暂停。恢复不清除原权限暂停、不重新执行uncertain，也不转移文档或Team权威。

## 兼容与限制

- 归档/恢复要求所有当前成员节点在线且支持roomLifecycleVersion=1；否则明确拒绝，当前版本不做离线归档。操作保存本机后按既有反熵同步补传，不承诺网络分区下所有节点同一时刻切换。
- 有密钥集群的state pull强制校验请求ID/请求方/应答方/规范化state绑定的回复proof，不能靠删除响应能力和generation降级跳过。旧节点无proof的回复明确失败，请全量升级。普通未使用生命周期的状态请求签名字节仍兼容；启用后的生命周期/参与资格/事件进入签名。不要退回旧版编辑这些房间。
- 空密钥集群仍是开放信任模式。集群沿用共享密钥信任，没有引入节点独立私钥。
- 当前管理操作只提供owner面板上的人类Leader入口；Agent Leader没有新增归档工具。人类历史阅读也不等于可恢复或可接管。
