**版本**：v0.2.0
**创建日期**：2026-11-02

## 1. 需求概述

### 1.1 背景和问题

现有 dsh-lan-mesh（局域网协作）插件提供：节点发现（UDP 广播）、点对点消息、房间/任务协作、agent 联邦。用户希望以 `@contexera/dsh-agent-team` 插件的体验为参照，对当前界面的交互进行澄清与优化补全。核心痛点：进入房间后无法后退（只能退出房间）、会话下拉选择多余、没有总览首页。

### 1.2 业务目标

- **核心目标**：以 agent-team 为参照，重塑面板为「指挥中心（OPC）」形态：human 固定身份作为指挥官，左侧导航 + 右侧明细；进入房间可一键返回首页；保留并强化「human 指挥一堆 agent 干活、agent 之间互传信息」的协作模型。
- **成功标准**：
  1. 打开面板默认落在首页总览（本机身份卡、在线节点、可加入项目）；
  2. 左侧提供「我的房间 / 收件箱 / 任务看板」三个导航入口，点击后在右侧展开明细；
  3. 房间详情页左上角有「← 返回」按钮，返回不退出房间；重新进入房间展示最新内容（不保留滚动位置）；
  4. 界面不再出现会话下拉，一切操作以 human 身份进行；
  5. 本机 agent 可被拉入房间干活（invite 保留），远端 agent 可联络（dial 保留），agent 成员之间可互传信息。

### 1.3 功能边界

**本次范围**：
- 新增「首页/总览」视图（面板默认落地页：本机身份卡、在线节点、可加入项目）
- 左侧导航重构（我的房间 / 收件箱 / 任务看板 三入口，右侧展开明细）
- 房间详情页提供「← 返回」按钮（返回不退出房间；不保留滚动位置）
- 移除「会话下拉选择」，身份固定为 human（指挥官）
- 保留 invite（拉本地 agent 会话进房）与 dial（联络远端 agent）功能，语义统一为「human 指挥 agent」
- 明确 agent 成员之间可互传信息（房间内消息/任务流转）

**不在范围**：
- ❌ 跨机多 Human 协作：维持现状（单 Host 单 Human，同 agent-team）
- ❌ 后端协议改造：全部为前端 UI 与交互语义调整，复用现有 10 个 lan_mesh_* 工具
- ❌ 持久 agent 的 memory/skills 体系（agent-team 的成员持久化能力，超出本插件当前数据面）

---

### 1.4 用户分析 【存量迭代可简写】

沿用现有用户：使用 dsh-lan-mesh 插件进行局域网多节点协作的 DSH 用户；期望将插件当作多 agent 协作指挥台使用。

## 3. 业务规则详解

- **导航规则**：左栏导航高亮当前右侧视图；当前视图 = 首页总览 | 我的房间明细 | 收件箱明细 | 任务看板明细 | 房间详情。
- **返回规则**：从「我的房间」明细进入房间详情后可返回「我的房间」明细；从其他入口不直接进入房间（房间只能从「我的房间/可加入项目」进入）。返回不执行 leave，房间 membership 保持。
- **滚动规则**：进入/返回房间不保留滚动位置，每次进入展示最新消息（底部）。
- **身份规则**：sessionId 恒为 human；invite 拉入的是 agent 会话（非 human 身份切换）。

## 4. 页面设计 【前端需求填写】

### 4.1 整体布局

**左栏（Rail）自上而下**：本机身份卡（human 头像/昵称）→ 导航三入口（我的房间 / 收件箱 / 任务看板）→ 新建房间按钮。
**右主区**：随导航切换——默认首页总览；点击导航入口显示对应明细页；我的房间明细中点房间行进入 RoomPane。

### 4.2 首页总览（FR-01）

| 变动类型 | 元素位置 | 元素描述 | 详细说明 |
|---------|---------|---------|---------|
| 🆕 新增 | 右主区 | 本机身份卡 | human 身份卡（复用现 lm-ident 卡内容） |
| 🆕 新增 | 右主区 | 在线节点列表 | 现有 peers 卡片整体迁入 |
| 🆕 新增 | 右主区 | 可加入项目 | 现有「可加入项目」段（onJoin）从左栏迁入，附「新建房间」入口 |
| 🆕 新增 | 右主区 | 我的房间 | 现有「我的房间」列表从左栏迁入（含 room 行点击） |
| ✏️ 修改 | 左 Rail | 导航三入口 | 「我的房间/收件箱/任务看板」图标+文字入口，切右区视图 |

### 4.3 明细页

| 页面 | 内容 | 数据来源 |
|------|------|---------|
| 我的房间明细 | 房间列表（名称/成员数/在线状态），点击进入 RoomPane | `rooms()` |
| 收件箱明细 | 点对点消息列表（同现有点对点区） | inbox 轮询 |
| 任务看板明细 | 跨房间任务汇总（状态/负责人/所属房间），可按房间分组 | `tasks()`/现有任务接口 |

### 4.4 房间详情页（FR-03）

| 变动类型 | 元素位置 | 元素描述 | 详细说明 |
|---------|---------|---------|---------|
| 🆕 新增 | RoomPane 头部左侧 | 「← 返回」按钮 | 返回上一视图（我的房间明细/首页），不清除成员身份 |
| ⚪ 无变化 | RoomPane 其余 | 任务区、聊天区、成员列表 | 保持现状；assignee/邀请目标均为 agent 会话 |

**交互要点**：

| 操作 | 触发方式 | 正常行为 | 异常处理 |
|------|---------|---------|---------|
| 打开面板 | 自动 | 默认首页总览 | 无 |
| 点击导航入口 | 点击左栏 | 右侧切换明细页 | 无 |
| 进入房间 | 我的房间明细/可加入项目中点击 | 进入 RoomPane，头部有返回按钮 | 无 |
| 返回 | 点击 RoomPane「← 返回」 | 回到上一视图；不退出房间 | 无 |
| 重新进入房间 | 再次点击房间 | 展示最新消息（不保留滚动位置） | 无 |

## 7. 约束与假设

### 7.1 约束

- 复用现有 10 个 lan_mesh_* 工具，不新增后端接口。
- 不引入 agent-team 的持久 agent（memory/skills）数据面。

### 7.2 假设

- 「强制 human」=接入房间与一切操作以 human 身份进行；agent 成员通过 invite/dial 进入（human 不再以 agent 会话身份操作）。
- 「任务看板明细」为面板级跨房间任务汇总；如与预期不符，实施时回退为房间内任务区（现状）。
- 「收件箱明细」内容 = 现有点对点消息（P2P），不含房间聊天。
