# 静态节点地址（0.4.3）

广播被阻止或跨网段时，在插件owner配置中增加staticPeers。对端nodeId与实际HTTP端口可由其本机节点信息确认，不能用房间ID或会话ID代替。两端各自配置对方：

```yaml
staticPeers:
  - nodeId: node-xxxxxxxx
    address: 192.168.1.20
    httpPort: 45871
    name: laptop
```

支持IPv4或主机名，不支持URL、路径、凭证及IPv6字面量；最多64条，nodeId和端点必须唯一，错误配置明确报STATIC_PEER_CONFIG，不静默忽略。配置后重新加载。

静态地址优先于同nodeId的广播记录，但不是信任名单。原clusterSecret、trustedPeers及Worker本机目录/会话授权保持原规则。配置地址本身不表示在线；只有实际状态同步通过并确认响应nodeId一致后才进入在线列表，失败或20秒未验证后不再标在线。未验证的配置目标仍保留，周期同步会重试。

对端必须可通过配置地址访问，并使用兼容版本。0.4有密钥状态回复要求proof，旧端无proof仍拒绝，不因静态配置而降级。身份不符时不导入其状态，也不向该静态端点推送房间状态。网络仍为HTTP，静态地址不是TLS或节点独立密钥隔离。

发送普通消息、Room消息、任务与文档前复用有效身份缓存，过期则先做签名状态探测；探测失败不发送正文。首次静态同步即使本机没有新改动也补推历史；部分目标失败不会清除待补传标记，恢复后继续同步。

自动化使用真实localhost HTTP验证禁广播记录下的同步、错误身份、白名单拒绝和在线投影；不是物理跨网段、真实模型或三机验收。故障时先核对实际nodeId、实例端口、路由和升级版本，不关闭认证以求通过。
